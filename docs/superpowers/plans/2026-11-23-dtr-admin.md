# Troy DTR Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a session-authenticated admin at `/TroyLeaveFiling/admin/` for branch management, employee branch/work-arrangement assignment, and home-location approvals.

**Architecture:** New PHP admin handlers live in the existing Troy portal API and reuse its session auth, DB helpers, `portal_review_home_location()`, and profile update semantics. A trimmed React/Vite app in `admin-src/` builds into `admin/` and calls the same-origin portal API. `TLFwithadmin` holds all work; `main` stays untouched.

**Tech Stack:** PHP 8.2+/MySQL 8, React 19, Vite 7, TypeScript strict, React Router 7, Leaflet/react-leaflet, Tailwind CSS 4, lucide-react.

**Spec:** `docs/superpowers/specs/2026-11-23-dtr-admin-design.md`

## Global Constraints

- Base URL: `/TroyLeaveFiling/admin/`; API base: `/TroyLeaveFiling/portal/api`.
- Auth: existing `index.php` employee login + portal session cookie; no new login, no bearer tokens.
- Roles: `admin` → all three screens; `approver` → Home Locations only; everyone else → 403.
- Writes require `X-Requested-With: XMLHttpRequest` (the portal API enforces it).
- All SQL uses prepared statements. Employee ids are strings (`idno` varchar).
- Bulk assignment accepts 1..2,000 idnos per request; "Select all matching filters" refuses to exceed that instead of truncating.
- Joins across `employeefiletbl` and portal tables use the existing `COLLATE utf8mb4_general_ci` pattern.
- Timestamps display in `Asia/Manila`.
- Keep `main` untouched; commit every task on `TLFwithadmin`.
- Built `admin/` output is committed, matching `portal/assets` tracking.
- No external CDN for scripts, fonts, or Leaflet icons; only OpenStreetMap tiles are external.

## Review Focus

1. **Search input containing `%`, `_`, or backslash** — must be treated as literal text, not SQL wildcards; a user searching `100%` must not match everything.
2. **Stale or unknown idnos in a bulk request** — must be skipped and reported, not silently inserted or fatal.
3. **Deactivate racing a bulk assignment** — must not leave an employee assigned to an inactive branch; branch rows are locked in both paths.
4. **Arrangement-only bulk assignment for an employee with no profile** — new profile must be created with `onsite` default and a null branch, with the "cannot punch onsite without branch" warning returned.
5. **Reviewing a pin that was already approved/rejected or superseded** — must return a clear 422, not overwrite another employee's current pin.
